# 운영 절차

## 일상 점검

- 오류 로그는 이벤트·상태·건수만 남습니다. 토큰·문서 본문·수신처가 로그에 없는지 정기적으로 확인합니다.
- `imq_tokens`의 만료 갱신 실패, `/api/imweb/products`의 401/429, `/api/billing/events`의 401(서명 실패)를
  모니터링합니다.

## 토큰 수명과 회전

- 접근 토큰 2시간, 갱신 5분 전 선제 갱신.
- 갱신은 저장된 `refresh_token`이 그대로일 때만 반영(compare-and-set). 실패는 재설치가 필요하다는 뜻이라
  낡은 토큰을 돌려주지 않습니다.

## 연동 해제와 청구 중단

1. 사용자가 앱에서 `연동 해제`를 누릅니다.
2. `PATCH /site-info/integration-cancellation` 호출(실패해도 토큰은 삭제).
3. 토큰 삭제, `imq_shops.uninstalled_at` 설정.
4. `cancelSubscription`으로 다음 회차 청구 중단.
5. 견적 문서는 남습니다. 전체 삭제 요청은 이메일로 받아 파기합니다.

웹훅(`/api/webhooks/imweb`)은 보조 수단입니다. 유실·미전송이 있을 수 있어 이것만 믿지 않습니다.

## 데이터 삭제 정책

- 결제 취소(환불)와 데이터 삭제는 별개입니다.
- 견적 초안·확정본은 이용자 요청 시 삭제합니다.
- 결제 증빙은 관련 법령이 정한 기간과 방법을 따르며, 임의 숫자로 기간을 정하지 않습니다. 구체 기간은
  계약·법률 검토 후 확정합니다.

## 장애 대응

| 증상 | 확인 | 조치 |
|---|---|---|
| 설치 후 상품이 안 보임 | `/api/auth/session`의 `unitCurrency` | KRW 유닛인지, 권한 승인 여부 확인 |
| 401/재설치 요구 | 갱신 토큰 만료·권한 철회 | 앱 재실행으로 재동의 |
| 429/일시 장애 | API 응답 상태 | 백오프 후 재시도, 사용자에게 안내 |
| 결제가 반영 안 됨 | `/api/billing/events` 401 | 웹훅 시크릿·서명 형식 확인 |
