# 심사 제출 준비

근거: [공식 승인 프로세스](https://developers-docs.imweb.me/guide/프로세스-확인하기),
[앱 연동 가이드](https://developers-docs.imweb.me/guide/앱-연동하기).

## 순서

1. 새 앱 정의·개발자센터 등록(리뷰 앱 등록을 덮어쓰지 않음).
2. 연동 개발·자체 테스트(유효한 소유 테스트사이트).
3. 앱/API 승인 요청: 심사자가 실행할 테스트 방법·샘플·기능/제약을 제출. 요청일·앱 ID·상태 기록.
4. 심사·수정 대응: 접수/반려/수정/재제출을 구분. 승인 요청 자체를 승인으로 기록하지 않음.
5. 견적 앱용 계약 협의·전자서명(서비스 범위·수익쉐어·가격/체험·정산 기준).
6. 스토어 콘텐츠 제출: [담당자 제공 콘텐츠 가이드](https://imweb.notion.site/imweb-3227d8bbc84749c98f8bcb7a73793c35)의
   실제 규격에 맞춤. 현재 이 본문 접근 실패로 이미지 크기·필수 개수는 **미확인**이며 임의로 만들지 않음.
7. 게시·외부 경로 확인: 공개 목록 → 상세 → 설치 → 첫 견적 → 결제/체험.

## 심사자에게 제공할 것

- 테스트용 사이트 접속 URL과 절차: 로그인 → 앱 실행 → 상품 선택 → 견적 확정 → XLSX/인쇄 → 연동 해제.
- 합성 상품·견적이 담긴 데모: `/demo`(설치 없이 동작).
- 기능/제약 안내: 주문·결제·회원 개인정보를 다루지 않음, PDF는 브라우저 인쇄 저장, 부가세 자동계산 없음.
- 최소권한 대조표: `site-info:read`(사이트/유닛), `site-info:write`(연동완료·해제), `product:read`(상품/옵션).
  리뷰·회원·주문·상품 쓰기 권한은 요청하지 않음.
- 서비스 URL·redirect URI가 등록값과 문자 단위로 일치.

## 제출 전 체크

- [ ] 개발자센터 권한관리와 요청 scope 일치
- [ ] 서비스 URL/redirect URI 일치
- [ ] 운영 DB·시크릿이 새 값(기존 제품과 미공유)
- [ ] 정책 페이지(개인정보·지원/약관/환불) 게시
- [ ] 가격/체험/정책/계약 문안 정합성
- [ ] `npm run typecheck / lint / test / build` 통과
- [ ] 실제 브라우저 흐름(설치→첫 견적→저장→재접속→확정→XLSX·인쇄→해제) 확인
